05

AI素材の「仕上げ」について

AI生成だけでは完結しない、という現実への理解です。

70点の素材を、広告に耐える形へ

AIで生成した映像は、そのままでは「広告」として成立しにくいと感じています。どこか不自然だったり、メッセージが弱かったり。あくまでベース素材、という印象です。

だからこそ、生成後の仕上げ工程の重要性を強く感じています。テロップで視線を誘導する、UGC風に崩して親近感を出す、音声や「間」で感情を操作する——そうした編集の積み重ねが、70点の素材を広告に耐えるレベルに引き上げるのではないかと考えています。

自分はまだこの領域を学んでいる途中ですが、AI生成と仕上げの両方を意識して制作に取り組んでいます。

06

FAILMAP — 制作プロセスの可視化

AI動画制作の「なぜうまくいかなかったか」を構造的に整理するための、
自分なりの道具です。

なぜFAILMAPが必要だと思ったか

AI動画制作では、失敗の原因がブラックボックスになりやすいと感じています。同じプロンプトでも全然違う映像が出てきたり、「なんとなくダメだった」で終わってしまうことが多い。

その「なんとなく」を放置しないために、各ステップの失敗要因を分解して、次の仮説に接続する仕組みとしてFAILMAPを使い始めました。

完璧な管理ツールではありませんが、ブラックボックスを放置しないための整理の仕組みとして使っています。

各ステップの安定度マップ

↓

△ 判断基準が曖昧

↓

✓ 比較的安定

フック→展開→CTAの構成は型化できてきている

ここから見えてきたこと

1

AI生成ステップが最大のボトルネック。
完全なコントロールは難しいけれど、プロンプトのテンプレート化と選定基準の明文化で、ある程度は安定させられる可能性がある。

2

「失敗の記録」が次の改善の起点になる。
うまくいった制作物だけでなく、破綻した制作物の原因を残しておくことで、同じ失敗を繰り返しにくくなると感じている。

3

全工程の安定化は、まだ遠い。
正直なところ、まだ試行錯誤の途中。でも「どこが不安定か」を可視化できたことは、小さな一歩だと思っている。

How to Update（差し替えガイド）

🚀 動画差し替えの最短手順

  • ① videos/ にMP4を入れる
  • ② cases 配列の src をそのファイル名に書き換える
  • ③ 公開してスマホで再生確認する

動画ファイルの詳細

  • 動画ファイルを videos/ フォルダに配置
  • ファイル名規約：case01.mp4, case02.mp4 ...（連番）
  • 推奨：MP4（H.264）、9:16比率、10MB以下
  • サムネ画像が必要なら poster にパスを指定（任意）

ケースの追加・変更

ページ末尾の <script> 内にある cases 配列にオブジェクトを追加するだけでカードが自動生成されます：

cases.push({
  id: "06",
  title: "新しい訴求",
  src: "videos/case06.mp4",
  poster: "thumbs/case06.jpg",  // 任意
  hook: "フックのテキスト",
  hypothesis: "検証したい仮説",
  finishing: "仕上げ方針"
});

公開手順（GitHub Pages）

  • GitHubにリポジトリを作成し、このHTMLと videos/ フォルダをpush
  • Settings → Pages → Branch を main に設定
  • 数分で https://username.github.io/repo-name/ に公開される

公開手順（Cloudflare Pages）

  • GitHubリポジトリを接続、またはファイルを直接アップロード
  • ビルドコマンドは不要（静的ファイルのため）
  • カスタムドメインも設定可能
